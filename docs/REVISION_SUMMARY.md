# Pre-submission revision: what changed, and what forced it

Baseline: `paper/main.tex.prephases.bak` (75,588 characters). Current: 76,516. The manuscript is
**10 pages**, 0 overfull boxes, 0 undefined references, 0 unresolved `[NOT RUN]` markers, which is
the constraint the revision worked under throughout: IEEE TCCN charges $220 per page above ten, so
every addition below had to be paid for by a cut.

Every number in the manuscript is a macro generated by `paper/make_numbers.py` from a JSON file in
`code/results/`. Nothing below was typed by hand.

## 1. Findings that changed a claim in the abstract, contributions or conclusion

### 1.1 A quantised price *does* reach the learned arm. The old claim was an artefact of coding.

The manuscript previously said, in the abstract, in contribution 2, in Section VII-B and in the
conclusion, that **no quantised pricing configuration reaches the learned arm**. That was true of
the sweep behind it and false of the baseline it claimed to characterise.

`pricing_budget.py` fits its quantiser levels once, at `p = P_max * 1`, and never refits
(`pricing_budget.py:100-113`). The pricing loop starts at `0.5 * P_max` and moves the price
distribution off that operating point immediately, so every round after the first quantises a moving
scalar against a stale codebook. That is why more rounds never helped: `b=1` plateaued near 0.56
whether `K` was 6 or 192.

`pricing_variants.py` re-runs the same budgeted sweep with five ways of coding a moving scalar
(`absolute`, `differential`, `sign` with Jayant step adaptation, `adaptive` log-uniform range
tracking, `dithered`), price widths to 12 bits and budgets to 22,601 bits. Result:

| coding scheme | best ratio | at width | at budget |
|---|---:|---:|---:|
| absolute (the old baseline's coding) | 0.8723 | 12 | 5,376 |
| **differential** | **0.9713** | 12 | 10,752 |
| adaptive-range | 0.7908 | 10 | 5,376 |
| sign-delta | 0.7073 | 12 | 1,344 |

The learned arm reaches 0.9481 on 42 bits. Differential pricing first passes it at **0.9594 on
1,344 bits**, 32x the learned budget, and only at price widths of 10 bits or more.

**The paper now says that**, in all four places. The claim it makes instead is stronger, because it
survives a baseline that was given every advantage: the learned symbol is roughly 32x cheaper at the
budget where a well-coded classical one first matches it. The frontier claim is untouched — 0.9713
on 10,752 bits is still dominated by centralisation at 0.9804 on 2,048.

### 1.2 The codebook is not what makes the learned arm work

A straight-through binary code (DIAL/CommNet: a per-bit sigmoid, no codebook, no entropy bonus)
lands within 0.0111 of the VQ codebook arm across six budgets and five seeds, and is *ahead* at the
three smallest budgets (+0.0111 at B=1). Two unrelated mechanisms for producing a learned symbol
land in the same place, while quantised channel state at the same budget does not. Contribution 2's
sentence "a classical message is a value that must be accurate; a learned one is an index whose
meaning is trained" is now supported by an arm that has no index table at all.

### 1.3 Rounds do not trade evenly against width, and the paper's R=1 is not the best point

At a matched 42-bit budget: B=6 over one round scores 0.9352, B=3 over two 0.9559, B=2 over three
0.9571 — a spread of 0.0219. These cells all run with the entropy bonus off, so the fair
cross-reference is Table II's bonused single-round arm at 0.9481, which multi-round still beats by
0.0090 at the same bit cost.

This is reported plainly rather than smoothed over: rounds buy the gain with latency where bits buy
it with bandwidth, the overhead accounting assumes R=1, and this is now named as the clearest
direction in which the operating point could be improved. The corresponding open-problem bullet in
Section X is removed, since it is no longer open.

### 1.4 Remark 1's percentages were wrong

Remark 1 justifies the choice of circuit power by showing that a larger `P_c` flattens the two
objectives. Its four percentages were typed by hand. `pc_sweep.py` computes them: at the adopted
`P_c = 10` mW the oracle moves 36.2% in SE and 66.9% in EE across the preference axis (typed:
36.5%, 66.7% — close), and at `P_c = 100` mW it moves 9.1% and 14.3% (typed: **3.0%, 6.2%** — off by
a factor of three). The qualitative claim survives, the numbers are now generated, and the sentence
is reworded so "roughly four times as far" carries the argument rather than the word "only".

## 2. New result files, and the script that produces each

| File | Script | Full-pool cost |
|---|---|---|
| `results/pricing_budgeted_variants.json` | `pricing_variants.py` | 345 cells, CPU, ~4 h |
| `results/per_lambda.json` | `per_lambda.py` | 512 instances x 3 arms x 5 lambda, CPU, ~7 min |
| `results/learned_baselines.json` | `learned_baselines.py` | 51 runs, GPU, ~3 h |
| `results/pc_sweep.json` | `pc_sweep.py` | 2 oracle sweeps, CPU, ~2 min |

`code/run_full.sh {pricing|perlambda|learned|pc|all}` runs them, and every script takes `--smoke`
(64 instances, one seed) to prove the code path before the full pool. All four write their JSON
after each cell, so a kill costs one cell.

## 3. Guards added, and why

- **`make_numbers.py` refuses to summarise a partial grid.** PQV macros are withheld until all 345
  pricing cells exist; LB macros are withheld per arm. This is not cosmetic: the sweep visits price
  widths in increasing order and the differential arm improves with width, so summarising early
  understates the strongest baseline *in the direction that flatters our own claim*.
- **`make_figures.py` applies the same rule** to `fig_pricing_budget_curve`.
- **`qa.py`** registers the four new evidence files and reports grid completeness as a check.
- **`paper/audit_literals.py`** regenerates `docs/HARDCODED_NUMBERS.md` and, with `--check`, fails if
  it is stale. This is what caught 1.4, plus four configuration constants typed into the prose that
  Table I already generates. Surviving literals: 31 -> 21, all now plot limits, ticks or swept
  values.
- **`make_numbers.py` no longer shadows manuscript-local macros.** It emitted a
  `\providecommand` for any undefined name starting with a family prefix, which broke the
  manuscript's own `\newcommand{\MISSINGPROBE}` ("MI" is a family).

## 4. Defects fixed

- `PQBudgetToMatch` emitted a bare `>` in text mode, which OT1 renders as an inverted question mark.
  Latent (the macro was unused) but the same bug had already corrupted every censored cell of the
  B* table.
- A pgfplots coordinate cannot survive an unresolved macro: the axis fails to parse and the build
  dies before any `[NOT RUN]` marker can be read off the page. The frontier's budgeted-pricing point
  is now decided outside the axis, so a missing result is loud in Table III rather than fatal.
- `check_single_objective_solvers` in `qa.py` crashed with a `TypeError` on a `per_lambda.json`
  written by a run still in progress. It now reports incompleteness instead of passing or crashing.
